# משחק הפוקימון על שולחן הפוקר - סיכום להמשך עבודה

הקובץ הזה מסכם את כל מה שנבנה בצ'אט עם Claude, כדי שאפשר יהיה להמשיך במחשב.

---

## משימה ל-Claude שבמחשב

הקוד מוכן ונבדק. נשאר רק להעלות אותו לאתר של BrawlClash.

1. הקוד נמצא בריפוזיטורי `itaydaniel1000-beep/kesef-hacham`, בענף `claude/pokemon-card-game-a5v2r5`, בתיקייה `pokemon/`.
   (אם צירפתי גם את `pokemon-game.zip`, זה אותו קוד בדיוק.)
2. להעתיק את כל התוכן של `pokemon/` לתיקייה חדשה `pokemon/` בשורש הריפוזיטורי `itaydaniel1000-beep/BrawlClash`.
   - הקבצים: `index.html`, `style.css`, `data.js`, `pokedex.js`, `engine.js`, `net.js`, `ui.js`, ותיקיית `art/` עם 21 תמונות.
   - **לא לשנות שום קובץ אחר ב-BrawlClash.** המשחק המקורי צריך להישאר כמו שהוא.
3. לעשות commit ו-push ל-`main` (זה הענף שממנו GitHub Pages מפרסם את BrawlClash).
4. אחרי דקה-שתיים המשחק יהיה זמין בכתובת:
   **https://itaydaniel1000-beep.github.io/BrawlClash/pokemon/**
5. לבדוק שהדף נטען ושאפשר ליצור חדר ולקבל קוד.

פקודות לדוגמה (מתוך תיקייה שבה BrawlClash משוכפל):

```bash
git clone --depth 1 -b claude/pokemon-card-game-a5v2r5 https://github.com/itaydaniel1000-beep/kesef-hacham.git /tmp/kesef
cp -r /tmp/kesef/pokemon ./pokemon
git add pokemon
git commit -m "feat(pokemon): online Pokémon card game on a poker table"
git push origin main
```

> למה לא בכסף חכם? האתר של כסף חכם מתעדכן מ-`BrawlClash/money-game` דרך `publish-kesef.sh`,
> ופרסום כזה היה מוחק תיקייה שנוספה ישירות ל-kesef-hacham.

## חוקי המשחק (כפי שהוגדרו)

**כללי**
- תמה: עולם הפוקימון. זירה: שולחן פוקר, 2 עד 5 שחקנים. משחק **שיתופי**: כולם מנצחים או מפסידים יחד.

**פתיחה**
- יש 5 פוקימונים התחלתיים: בולבזאור, צ'רמנדר, סקווירטל, פיקאצ'ו, איווי.
- כל שחקן מטיל קובייה. לפי התוצאה (הגבוה ראשון) כל אחד בוחר פוקימון התחלתי. אי אפשר לבחור פוקימון שמישהו כבר לקח.

**סבב**
- פוקימון פראי עולה מהחבילה.
- כל שחקן מטיל את הקובייה שלו כדי לקבוע את סדר התורות.
- בתורו השחקן בוחר:
  - **תקוף:** בוחר עם איזה מהפוקימונים שלו לתקוף (תצוגה של פוקימון אחד, חצים ימינה/שמאלה, "חזור", "בחר").
    הנזק = החוזק של התוקף × המכפיל לפי טבלת הסוגים של הסדרה. כל תקיפה מגדילה את סיכויי התפיסה. התקיפה מסיימת את התור.
  - **תפוס:** מופיע "בטוח?" עם סיכויי התפיסה מעליו.
    - "לא" - חוזר לבחירה בין תקוף לתפוס.
    - "כן" - גלגל מזל. הצליח: הפוקימון עובר לשחקן ונשאר אצלו. נכשל: התור עובר לבא בתור, והפוקימון נשאר ושאר השחקנים יכולים לנסות לתפוס.

**סוף סבב בלי תפיסה**
- הפוקימון הפראי תוקף פוקימון אקראי של אחד השחקנים.
- אחר כך הוא חוזר למקום אקראי בחבילה עם חיים מלאים, ופוקימון חדש עולה.

**חיים ומוות**
- פראי שאיבד את כל החיים חוזר למקום אקראי בחבילה.
- פוקימון של שחקן שמת לא משחק עד המרפאה.
- מרפאה כל 5 פוקימונים פראיים: כל הפוקימונים חוזרים לחיים מלאים.
- שחקן בלי פוקימון חי מדלג על התורות שלו.
- **אם לאף שחקן לא נשאר פוקימון חי - כולם מפסידים** ומתחילים מחדש.

**הקרב האחרון**
- כשהחבילה נגמרת מגיע מיוטו. ניצחון - כולם מנצחים את ההרפתקה. הפסד - כולם מפסידים. בשני המקרים מתחילים מחדש.

## מולטיפלייר (כפי שהוגדר)

- **לובי:** מקלידים שם פעם אחת. כפתור "משחק" ← "אקראי" או "חדר".
- **אקראי:** בוחרים מספר שחקנים (2-5), והמשחק מתאים לשחקנים אחרים שבחרו אותו מספר. מחכים בלי הגבלה.
- **חדר:**
  - יצירה: בוחרים כמה שחקנים ומקבלים קוד מספרים. הקודים מוקצים מהקטן לגדול: 1-9, אחר כך 10-99, אחר כך 100-999...
    המשחק מתחיל אוטומטית כשנכנסו כל השחקנים.
  - כניסה: מקלידים את הקוד, נכנסים ומחכים להתחלה.
- **במשחק:** כל שחקן בטלפון שלו. כולם רואים בדיוק את אותו משחק: אותן קוביות, אותו גלגל, אותה חבילה.
  מי שלא בתור רק צופה.
- **20 שניות לתור.** לא פעל - התור עובר לבא. (לא הטיל קובייה או לא בחר התחלתי - נעשה בשבילו אקראית.)
- **שחקן שיוצא:** יוצא מהמשחק, והפוקימונים שלו (כולל ההתחלתי) חוזרים לחבילה.
  בקרב האחרון - הקרב ממשיך בלעדיו והקלפים שלו נעלמים עד המשחק הבא.
- אין מצב "כולם על טלפון אחד".

## החלטות שלא הוגדרו במפורש (אפשר לשנות)

1. **הקרב האחרון:** מיוטו, אי אפשר לתפוס אותו. חיים = 120 × מספר השחקנים. תוקף פעם אחת לכל שחקן בכל סבב. לפני הקרב כולם מתרפאים.
2. **סיכויי תפיסה:** לכל פוקימון סיכוי בסיסי, שעולה ככל שיורדים לו חיים (עד 95%).
3. **פוקימון שנתפס** נשאר עם החיים שהיו לו ברגע התפיסה, עד המרפאה.
4. **נתונים:** כל 1025 הפוקימונים נמצאים ב-`pokedex.js`. בכל משחק נשלפים לחבילה 15 פראיים באקראי מתוכם (`CONFIG.deckSize`).
   סוגים, חיים וחוזק לקוחים מ-PokeAPI (חיים × 2). סיכוי התפיסה מחושב מקצב התפיסה בסדרה. השמות בעברית הם תעתיק לפי ההגייה.
5. **פוקימון שחוזר לחבילה** נספר כאחד מ-5 הפראיים בדרך למרפאה.
6. ההגדרות נמצאות ב-`pokemon/data.js` (`CONFIG`, `STARTERS`, טבלת הסוגים), והפוקימונים ב-`pokemon/pokedex.js`.

## איך הקוד בנוי

| קובץ | מה יש בו |
|---|---|
| `data.js` | סוגים, טבלת יתרונות, התחלתיים, `CONFIG` |
| `pokedex.js` | כל 1025 הפוקימונים: שם בעברית, סוגים, חיים, חוזק, סיכוי תפיסה |
| `engine.js` | כל חוקי המשחק. רץ רק אצל המארח, מגריל את כל המזל ושולח לכולם את אותו מצב |
| `net.js` | חיבור בין הטלפונים דרך PeerJS (כמו ב-BrawlClash), בלי שרת משלנו |
| `ui.js` | לובי, חדר המתנה, השולחן, הגלגל והטיימר |
| `style.css` | עיצוב |
| `art/` | תמונות של ההתחלתיים, הבוס ועוד כמה. השאר נטענות מהמאגר הפתוח של PokeAPI ב-GitHub |

**איך הרשת עובדת:**
- כל חדר הוא "כתובת" בשירות הציבורי של PeerJS (`pokemon-table-itay-v1-room-<קוד>` או `...-rand-<מספר שחקנים>-<מספר>`). מי שתופס את הכתובת הוא המארח.
- המארח מריץ את `engine.js`. שאר השחקנים שולחים בקשות ("הטלתי", "בחרתי", "תקפתי", "תפסתי") ומקבלים את המצב המלא.
- דופק כל 3 שניות. מי ששותק 15 שניות נחשב כמי שיצא.
- **אם המארח יוצא:** השחקן הבא ברשימה הופך למארח וממשיך מאותה נקודה (כל שחקן מחזיק עותק של המצב).

**בדיקות:** `?peer=127.0.0.1:9000` מחבר לשרת PeerJS מקומי, ו-`?speed=8` מריץ את הזמנים פי 8 מהר יותר.
נבדקו עם כמה דפדפנים: חדר עם קוד, קוד שגוי, התאמה אקראית ל-4, שחקן שיוצא, מארח שיוצא, טיימר של 20 שניות.
אחרי יותר מ-2,000 צעדים כל הדפדפנים ראו מצב זהה.
